### 1.1 Invariants verified — no finding
- **Exactly-once send (F6/T16).** `drafts.send` has one production call site (`sender.ts` → `executeDraftSendProtocol`); create/update/send/save/delete all pass `retryTransient:false`, so the client's transient ladder never re-issues a mutation. Recovery is `getDraft` present ⇒ resend / 404 ⇒ sent; the crash-between-create-and-persist window uses a bounded 6×10 s Message-ID search and parks in `needs-review`; a 404 on `drafts.update` after a positive probe parks rather than sends (right, since T17 made mirrored drafts sendable from Gmail web).
- **Mirror ↔ sender hand-off.** The mirror persists a freshly minted `gmail_draft_id` even after the row has left `composing` (`mirror.ts:314-319`), and the sender waits for mirror idle then re-reads the row before creating — a checkpoint racing a send cannot orphan a Gmail draft.
- **Two-way draft sync (T14D).** `planDraftConflict` = open wins → revision pair beats clocks → LWW by timestamp; matches the plan.
- **Reducer / contacts (T13).** `persistThread` clears and re-inserts each message's contact contributions in one transaction (refetch-idempotent), filters `DRAFT`/`CHAT`, excludes `SPAM`/`TRASH` from contacts, keeps existing bodies on metadata refetches, replays pending intents afterwards.
- **Cursor grammar.** Retired `sent`/`sent:<token>` cursors route to `all-mail`; lifetime sweep is skip-if-present with per-page checkpoints; footer states are honest (`quota-wait` renders "Quota pacing").
- **Untrusted mail (§6).** Every mail anchor is forced `target=_blank rel=noopener noreferrer` (DOMPurify hook + `<base target>`), the frame sandbox has no `allow-scripts`, DOMPurify's default URI policy blocks `javascript:`/`file:`, `will-navigate` is prevented, `setWindowOpenHandler` routes to `shell.openExternal`.

### 1.2 Bugs

**B1 · BUG · medium · FIXED here — `syncRemoteDrafts` judged a draft bound *during* the listing as remotely deleted.** `src/main/outbox/draftSync.ts:600-623`. `knownDrafts` is snapshotted before `drafts.list` pagination; the "missing" pass afterwards treated any bound `composing`/`drafted` row absent from `remoteIds` as deleted in Gmail. A row whose first mirror checkpoint (`drafts.create`, 3 s after typing stops) returned its id while the poller's listing was in flight is bound but absent from a listing that predates it. Consequences: a `drafted` row was DELETEd (re-imported next cycle under a new local id → flicker in `g d`, orphaned spool dir); a `composing` row had its binding cleared → the mirror created a **second Gmail draft** and the next cycle imported the first as another local row (kind `new` has no fingerprint fallback) → duplicates in Gmail and locally. Fix: skip rows whose id was not in `knownDrafts` (judged next cycle). Two unit tests added; the new one fails on unfixed code.

**B2 · BUG · medium · FIXED here — a failed token refresh during `drafts.create` sent the row into Message-ID verification and, after reconnect, parked a never-sent message in `needs-review`.** `sender.ts` create-catch wrapped only `GmailApiError` 4xx as "no remote mutation"; `GmailAuthError` (raised by the token endpoint *before* the request is issued, or after a 401 rejection) fell through to `handleError` → `gmail_draft_id` null → `verification-error` (row stays `sending`, no longer undoable). On reconnect `resumeOnlineWork` triggers the sender → `recover` → `verify-secondary` → six negative searches 10 s apart → `needs-review` ("check your Sent mail before resending") for a message that never reached Gmail; `last_error` read "Message could not be sent". Realistic: dev-mode refresh tokens expire ~weekly (README). Fix: `GmailAuthError` → `OutboxNoRemoteMutationError` + retryable preflight (row returns to `queued`, undoable, backoff, resumes on reconnect); `userFacingSendError` names the authorization. Unit test asserts `findByRfcId` is never called and the row sends after reconnect.

**B3 · BUG · low · proposal — one non-retryable mirror failure stalls every later draft's mirror.** `mirrorExecutor.ts:101-110`: on a non-retryable `GmailApiError` the drain returns with no timer and no per-row marker; `drainDraftMirrors` orders by `updated_at`, so the same row is selected first on every trigger (each poll cycle's `kickExecutor`) — newer drafts never mirror and Gmail gets one rejected request per cycle. Needs a per-row skip/backoff (in-memory `nextAttemptAt` map is enough; no schema change) or "continue to next row".

**B4 · BUG · low · edge, folded into S2 — `persistThread` returns early on a draft-only snapshot and never prunes.** `persist.ts:67-68`: when every message in an authoritative snapshot is `DRAFT`/`CHAT`, the function returns before `removeMissingMessages`, so a thread whose real messages were permanently deleted while a Gmail draft remains keeps stale rows locally until the S4 tombstone pass. Noted in M3-PLAN S2 where the message loop is being reworked.

**B5 · BUG · high (for the F6 zero-loss invariant) · FIXED here — `preserve.ts` destroyed table structure whenever a cell or row carried an attribute the editor cannot hold.** `composer/preserve.ts` `opaqueSourceRegions` cut a region at the unsupported `td`/`tr`; its slice was then sanitized in a *body* context, where the HTML parser drops `td`/`tr` and keeps only the text, so the "replacement" was bare text and the final parse foster-parented it out of the table (a marker in its place would be foster-parented the same way). Empirically (probe on main): `<td bgcolor="#eeeeee">Cell A</td><td>Cell B</td>` → `<table><tbody><tr><td>Cell B</td></tr></tbody></table>Cell A`, `issues: []` (no banner), identical in outgoing mail; `<tr bgcolor>`, `<td align>`, `<td valign>`, `<td style="…;overflow:hidden">` (a Google Docs paste) all mangled likewise. `bgcolor/align/valign` on cells are ubiquitous in real mail and Docs/Sheets pastes. Fix: a table-scoped unsupported element (`caption/col/colgroup/thead/tbody/tfoot/tr/td/th`) lifts its region to the nearest enclosing `<table>`, so either the whole table freezes as one exact opaque unit (content the sanitizer keeps but the editor can't represent) or — for presentational attributes the import sanitizer drops by documented T14C design — the table stays an editable table with every cell in place. Three unit tests added (all three fail on main; the existing 17 still pass). Note this keeps the documented rule that sanitizer-dropped attributes are not frozen; whether `bgcolor`/`align`/`valign` on cells should be *representable* is a separate product call (see C8 below).

**B6 · BUG · medium · report only — an inline reply composer is remounted full-window from a stale draft snapshot when the view changes without going through its exit path.** `Inbox.tsx:222-226` derives `inlineComposerDraft` from `readerOpen && selected.id === composerDraft.threadId`; `switchView` (339-349), `openOutbox` (351-361), and the notification-focus effect set `readerOpen=false` but leave `composerDraft`, so the keyed inline `<Composer>` unmounts and a full-window `<Composer draft={composerDraft}>` mounts from the object captured at open. The header nav and Outbox button stay enabled during inline compose (e2e `composer.spec.ts:857` pins that). `useComposerDraft`'s unmount only clears timers — no flush — so edits inside the ≤5 s checkpoint window are dropped, and checkpointed edits vanish from the editor and are overwritten in SQLite on the next keystroke. Fix direction: route those transitions through `inlineComposerRef.current.exitConversation()` as `closeReader` already does (486-492), plus an e2e that clicks "Drafts" mid-reply and asserts the draft body.

**B7 · BUG · low-medium · report only — bulk labelling shows one thread's state, applies to the whole selection, then clears it.** `Inbox.tsx:788-795` passes `targets={[focused thread]}` while `useTriage.ts:37-40` rewrites `threadIds` to `[...selectedIds]` and calls `clearSelection()`. Select 3, `l`, toggle a label the focused row already has → picker says "remove" → removes from all 3 (2 never had it); the next toggle in the still-open picker applies to the focused thread only. `LabelPicker` already supports multi-target `some` states. No e2e covers bulk labelling.

**B8 · BUG · low · FIXED here — sync progress bar clipped after #51.** `SyncStatus.tsx` kept `grid-cols-5` while `SYNC_STAGES` grew to 7, so `trash`/`reconcile` wrapped into a clipped second row (`h-[3px] overflow-hidden`) and every segment was half-height. Now `gridTemplateColumns` derives from `SYNC_STAGES.length`.

**B9 · BUG · low · FIXED here — composer paste handler was never removed.** `Composer.tsx` `PasteContentPlugin` created `onPaste` inside the root-listener callback, so `previous?.removeEventListener('paste', onPaste)` removed a different function than the one added; every effect re-run (dev StrictMode double-invoke, or a dependency change) left a handler behind → duplicate image/HTML insertion on paste. Hoisted the handler out of the callback.

**S1 · SECURITY · medium-low · report only — Lexical's own clipboard JSON path can mint unsanitized opaque regions.** `nodes/OpaqueHtmlNode.tsx` `importJSON` stores `serialized.html` verbatim, and `serialize.ts` runs `restoreOpaqueHtml` *after* `sanitizeOutgoingHtml` by design; `Composer.tsx`'s paste handler returns without `preventDefault` when `text/html` is empty, so Lexical's default importer parses `application/x-lexical-editor` (checked only against the public namespace `attn-composer`) and calls `importJSON`. A hostile web page's `copy` handler can therefore plant arbitrary raw HTML that lands unsanitized in the *outgoing* message (`StyledTextNode`/`ImageNode.importJSON` likewise accept raw `style`/`src`). No local execution (scriptless sandbox + CSP), so this is an outgoing-mail sanitization bypass, not XSS; exploitability depends on Chromium's cross-app custom-MIME clipboard transfer (plausible, untested). Fix: decode → `sanitizeDraftHtmlForImport` → re-encode in `OpaqueHtmlNode.importJSON`/`importDOM`, `sanitizeComposerStyle` in the other two `importJSON`s, or intercept the lexical MIME type in the paste handler.

**S2 · SECURITY · low — quote CSS filter misses `translate`/`rotate`/`scale`/`offset-*`, `text-indent`, and custom-property indirection** (`shared/mailSanitizer.ts:49-65`; `--m:-600px; margin-top:var(--m)` passes, `calc(0px - 600px)` is caught). Recipient-side cosmetics only.

**C8 · RESOLVED 2026-08-17 (SPEC §9 #18a) — the "Preserved … sent unchanged" banner overpromised for regions the import sanitizer already stripped.** Legacy presentational table attributes now survive both sanitizer gates and freeze their whole table as a byte-exact opaque region, so the banner tells the truth for them. Original finding: (`align/valign/bgcolor/…` are dropped by `ALLOWED_URI_REGEXP` applying to every non-URI attribute; the frozen token holds the *sanitized* region while `issues` still lists `td[align]`). The dropping is documented as intended (`preserve.test.ts:78-86`); the banner text and the T14C allowlist for legacy table attributes deserve one deliberate decision.

Other renderer items verified but low: `dateGroup` uses `Math.floor` on a start-of-day delta so the day after DST spring-forward groups yesterday as "Today" while `mailDisplay.ts` rounds (one day/year); Escape in a recipient field with autocomplete open closes the whole composer (no `data-composer-transient` on the suggestion list); fragment links inside mail open `about:srcdoc#x` externally; `useTriage`/`snoozeSelected` swallow rejections without a toast; unhandled `Promise.all` in `InitialHtmlPlugin`/`InlineQuote`/`OpaqueHtmlNode` if the account drops mid-compose.

**N2 · BUG (UI) · low · FIXED here** — `MailFooter` rendered the composer chord as "Mod / Enter send" (the `/` separator means *alternatives*, as in `J / K`), visible in `inline-reply.png`; the Send button showed ⌘↵. Hints now carry `chord: true` and render `⌘ + Enter`.
